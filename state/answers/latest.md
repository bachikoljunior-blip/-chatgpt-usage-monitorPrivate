結論から言うと、この制約では「商品を作って待つ」より、すでに発注金額が提示されている仕事を取りに行く方が圧倒的に速いです。

順位は次のとおりです。

1. GitHub上の報奨金付きIssueを解決する
2. 既存需要を検出してから、その需要専用の小商品をGumroadで作って直接提示する
3. 公開バグバウンティで、報奨対象が明確な脆弱性だけを調査する

ここでいう「最初の1円」は、まず「売上・報酬が確定して残高に計上された日」です。銀行着金まで求める場合、本人確認・税務情報・最低支払額で順位が変わります。

## 2. 人間操作がゼロまたは1回の候補

### 追加操作ゼロで実行可能

既存Gumroadの支払・税務設定がすでに有効なら、以下です。

- GitHub上で需要を検出→専用ツール作成→Gumroad販売
- YouTube検索向けの解決動画→Gumroad販売
- GitHub Pagesに無料診断版を置き、修復版をGumroad販売
- 既存GitHubアカウントから、報酬を直接Gumroad購入として支払ってもらえる小規模依頼
- 仕様変更・サービス終了を監視し、移行ツールを即日販売
- 公開Issueに対して無料の手作業解決を示し、反復利用できる自動版を販売

最後の方法は、無差別リンク投稿をしてはいけません。問題を実際に解決した回答を出し、「同じ処理を大量に行う場合だけ有料版」とする必要があります。

### 人間操作1回に収められる可能性がある

「一度のオンボーディング時間で、本人確認・税務・送金先登録をまとめる」という数え方なら、

- Algora等のGitHub bounty
- HackerOneなどのバグバウンティ
- GitHub Sponsors
- 既存の賞金コンテスト
- BOOTH、KDP、素材市場

ただし、審査差し戻しや追加書類が来れば1回では済みません。特にHackerOneは報酬受領に本人確認が必要で、有効な税務フォームと支払方法も必要です。[本人確認条件](https://docs.hackerone.com/en/articles/8399430-id-verification)、[支払条件](https://docs.hackerone.com/en/articles/8399426-payment-faqs)

したがって「本人確認には人間がまったく動かない」を厳格に適用すると、これらは実質利用不能です。AIが本人の代わりに本人確認を行うこともできません。

## 3. 上位3つと最初の1円まで

### 1位：報奨金付きGitHub Issue

現実的な期間：

- 報酬確定：3～21日
- 実際の着金：7～35日
- 難易度の低い、スポンサー資金確保済み案件を発見できた場合の中央値感：7～14日程度
- 人間操作：支払オンボーディング1回が必要になる可能性大

AlgoraはGitHub bountyと報酬受領を提供し、支払所要時間を2～7日と案内しています。[Algora料金・支払案内](https://algora.io/pricing/)

具体的な運用は、金額の大きいIssueではなく、

- 再現テストが既にある
- 受入条件が明文化されている
- 変更ファイルが少ない
- maintainerが直近7日以内に活動
- 他のclaimがない
- 報奨資金が明示されている

案件だけを監視し、最短でPRを出すことです。

失敗する主因：

- 先に他人がclaim・mergeされる
- 仕様が曖昧で追加作業が膨らむ
- maintainerが停止して報酬確定しない
- AI生成PRと見なされるほど検証が弱い
- 本人確認・送金登録を人間が行えない

### 2位：需要検出後に作る「一問題専用」Gumroad商品

現実的な期間：

- 初売上：7～45日
- 強い障害や終了期限に当たれば：1～7日もあり得る
- 需要選定を外すと：無期限
- 人間操作：既存Gumroadの支払設定済みなら0回

これは既存のゲーム制作キットの改良ではありません。先に商品を作らず、以下の条件を満たした問題だけ製品化します。

- 過去14日以内に同じ質問・Issueが5件以上
- 手作業の解決に30分以上かかる
- エラー文や製品名で検索できる
- 無料回答は存在するが一括処理ツールがない
- 購入者が個人開発者または業務担当者
- 24時間以内にCLIまたはデスクトップ実行物として作れる

例として、「あるSaaSのAPI廃止まで残り30日」という状況を検知し、無料の件数診断ページと、980円の一括移行CLIを同日に出します。関連Issueには診断結果と手動解決を提示し、大量処理だけ有料にします。

失敗する主因：

- 困っている人は多いが、支払うほどではない
- 無料の公式修正がすぐ出る
- 問題の発生数をGitHubの反応数と取り違える
- 投稿先の自己宣伝規則に抵触する
- Gumroadの購入摩擦や信頼不足

なお、Gumroadの通常取引には現在10%＋0.50ドル等の手数料があります。極端な1ドル商品は手数料比率が高すぎます。[Gumroad公式手数料](https://gumroad.com/help/article/66-gumroads-fees.html)

### 3位：公開バグバウンティ

現実的な期間：

- 有効報告の受理：7～60日
- 報酬確定：14～90日
- 着金：確定後さらに7～10日程度
- 人間操作：本人確認、税務、支払方法登録が必要。実質1回以上

自律エージェントとコード実行能力の相性はよいですが、対象は必ず明示されたスコープ内に限定します。最初は巨大Webサービスの一般的なXSS探索より、

- 新規公開されたAPI
- OSS依存関係と本番設定の不一致
- 認可差分を機械生成して比較できるAPI
- 報奨対象と除外項目が明確
- 報奨額表が公開されている
- 重複が少なそうな新規プログラム

に絞る方が合理的です。

失敗する主因：

- duplicate
- informative／not applicable判定
- 自動スキャン禁止条件への抵触
- 再現性不足
- 報奨対象外資産
- 本人確認不能

HackerOneは、報酬対象になってもすべての報告に賞金が出るわけではなく、現在は金銭報酬受領に本人確認を求めています。[HackerOne支払案内](https://docs.hackerone.com/en/articles/8395720-payment-preferences)

## 4. 現在の4施策の見込み

8か月で0円という実績を強く反映した推定です。正確な日数を統計的に断定できるだけのデータはありません。

| 現在の施策 | このまま続けた場合の初売上見込み | 判定 |
|---|---:|---|
| 放置クリッカー宣伝Shorts | 12か月～数年、または永久に0円 | 上位3案より明確に遅い |
| 無料ブラウザゲーム | 直接の課金経路がなければ「到達不能」 | 収益経路ではない |
| $25ゲーム制作キット | さらに12～36か月以上、または永久に0円 | 上位3案より明確に遅い |
| 無料デモ＋IndexNow | 単独では「到達不能」 | インデックスは販売経路ではない |

Shorts広告収益についても、現在の規模では現実的な最短経路ではありません。YouTubeの広告収益には原則として登録者1,000人に加え、過去12か月の公開視聴4,000時間または90日でShorts 1,000万回などが必要です。[YouTube公式YPP条件](https://support.google.com/youtube/answer/72851?hl=en)

2,435再生・登録者1人から見ると、これは「最初の1円を急ぐ」経路ではありません。

最も重要な判断は、無料ゲームやキットの改良を止めることではなく、「発注金額が既に存在する案件」だけを最優先キューにすることです。本人確認が完全に不可能なら、実行可能な本命は2位の「需要を確認してから作るGumroad小商品」に限定されます。それでも無差別な商品量産ではなく、発生中の具体的な障害を検知してから24時間以内に売る、という順序が必要です。
