```yaml
idempotent: true            # 何度実行しても害がない
done_marker: codex/outbox/2026-08-09.l.md
done_signal: "## 判定"      # 回答にこの文字列が無ければマーカーを置かない
```

## 起動したらまず（**定期実行なので、毎回ここから**）

あなたは定期的に、毎回まっさらな状態で起動されます。前回の記憶はありません。

**期限とマーカーの確認は、あなたの仕事ではありません。**
`.github/workflows/codex-inbox.yml` が `scripts/inbox-task.mjs` を先に走らせ、
`valid_until` が過ぎているか `done_marker` が既にあるなら、
**あなたはそもそも起動されません。** あなたが動いているなら、この task は
「期限内・未実行」だと確認済みです。**もう一度確かめ直さないでください。**

**push しないでください。届きません。** あなたが動いているサンドボックスの作業場所は
チェックアウトの外にあり、リポジトリにも資格情報にも届かないように作ってあります。
2026-08-09 まで、この指示は「push できるか試して、できなければ調査せず終えろ」と
書いてありました。**この経路では push は絶対にできないので、その指示のままだと
この口は永久に空振りするだけでした。**

**あなたの回答は、ワークフローが自動でコミットします。**
完了マーカー（`done_marker`）も、あなたの回答からワークフローが作ります。
だから**あなたがやることは、下の「今回やること」を実行して、答えを書くことだけ**です。

**ファイルを探さないでください。** 2026-08-09 の最初の実行で分かったことです。
あなたは空の作業ディレクトリで起動され、`codex/INBOX.md` も git も見つけられず、
「作業ディレクトリが空です」の一文だけを返して終わりました。**それが正常な挙動です。**
だから今は、**必要なものは全部あなたへの入力に貼り付けてあります**
（この指示の全文と、下の「背景」が挙げている `state/` のファイルの中身）。
**どのファイルが付いているかは、この本文の `=====` の見出しを見れば分かります。**
毎回その場で読み出して貼っているので、**古いことはありません。**

**`## 判定` の見出しを必ず書いてください。** ワークフローはこの文字列を探して、
「本当に仕事をしたか」を判定します。無ければマーカーを置かず、明日もう一度来ます。
**中身が無いのに見出しだけ書くのはやめてください。** それは仕組みを騙すだけで、
騙した先に得をする人がいません。

**答えが空なら、マーカーも残りません。** 明日もう一度この task が来ます。
それは正しい動作です。**空振りを隠すために、中身のない答えを書かないでください。**

**「確かめられなかった」は正しい答えです。** 空振りの回に仕事を作り出さないでください。

## あなたへ

このリポジトリを読める状態で、定期的に起動されています。
**毎回まっさらな状態で始まります。** 前回何をしたかは覚えていません。それで正常です。

**推測で答えないでください。** 実際に読んだ・実行した結果だけを書いてください。
確かめていないことは「未確認」と書いてください。**未確認を「無い」と書かないこと。**

## 背景

目標は**月収20万円を最短で**。**現在いくら売れているかは、下の `state/gumroad.json`
を見てください。** ここには書きません。書けば古くなります。

この指示のあとに、次の4つの中身がそのまま貼り付けてあります。**そちらを読んでください。**

- `state/eta.json` — 到達予測と、それを縮める候補が**速い順**に
- `state/constraints.json` — 何ができて何ができないかが**測定日と再検査期限つき**で
- `state/portfolio.json` — この持ち主が実際に公開しているものの**数え上げ**
- `state/gumroad.json` — **値段が付いている唯一のもの**と、その売上実績

**記憶ではなく、貼り付けられた内容で判断してください。**

## 今回やること

### 前回（task .k）は、買い手の種類を取り違えたまま訊きました

**まずこれを読んでください。** 貼り付けた `state/portfolio.json` の
`the_priced_artifact.who_it_actually_addresses` です。**ここに何が起きたかが書いてあります。**
要約はしません。要約すると、また同じ取り違えが起きるからです。

かいつまんで言えば、前回の調査は「ゲームのソースコードや制作キットを買う人」
＝**開発者**について訊きました。ところが商品説明が実際に呼びかけている相手は
開発者ではありません。**誰に呼びかけているかは、`state/portfolio.json` の
`the_description_names` に列挙してあります。そちらを読んでください。**

この2つは**集まる場所が違います。** だから前回の「どこに集まっているか」の答えは、
当たっているかどうか以前に、**別の人たちについての答え**です。

### だから今回は、正しい買い手層で訊き直します

**前回の答えを引き継がないでください。** あなたは毎回まっさらで、前回の回答も
持っていません。それで正しいです。**今回の3つの問いだけに答えてください。**

**なお、前回すでに片付いていて、今回は訊かないことが1つあります。**
「実績ゼロから同じ日に複数の場所へ出して初売上に届いた先例があるか」は、
買い手の種類に依らない問いなので、前回の答えをそのまま使います。
**もう一度調べないでください。**

### 訊きたいこと（**3つ。それぞれ別の節で答えてください**）

#### 1. この層は、この種のものに実際に金を払っているか

`state/portfolio.json` の `the_priced_artifact` と、`state/gumroad.json` の
値段を読んでから答えてください。**商品名・値段・呼びかけている相手は
そちらにあります。ここには書きません。**

訊いているのは「買いそうか」ではありません。**実際に金を払った実例**です。

- 小さな事業者（店舗・サロン・配信者・キャンペーン担当など）が、
  **自分のサイトに置く小さな遊べるもの**（ミニゲーム・診断・スタンプ・ガチャ・
  ポイント遊びなど、呼び名は何でもよい）に**実際に金を払った**実例
- 誰が・いくらで・何のために買ったか
- **買い切りだったか、月額だったか、制作を外注したのか**を区別してください。
  ここは重要です。**「作ってもらう」しか選択肢が無い層なら、
  自分で設定ファイルを書き換える商品は形が合っていません**
- **出典URLを必ず付けてください**

**払った実例が見つからないなら「なし」と書いてください。**
「払いそう」で埋めないでください。**それが一番害のある答えです。**

#### 2. その層は、どこに集まっているか（**規約と投稿条件つきで**）

**具体的な場所の名前**を挙げてください。日本語の場でも英語の場でも構いません。
**この持ち主は日本語で書いています**（商品説明が日本語であることは
`state/portfolio.json` から分かります）。日本語で投稿できる場があるなら、
**そちらを優先して挙げてください。**

場所ごとに、必ず次を調べてください。**ここが今回の核心です。**

- **その場所の規約は、自分の商品の宣伝投稿を許しているか。**
  許していないなら、**該当する規約の文言をそのまま引用**してください
- **できたばかりの、実績ゼロのアカウントでも投稿できるか。**
  カルマ・アカウント年齢・過去の参加回数・承認制・有料会員など、
  **投稿の前提条件**があるなら、その**数値と出典**を書いてください
- 条件が無いなら「無し」と書いてください。**「たぶん大丈夫」は書かないでください**

**規約を確認せずに場所の名前だけ並べないでください。** 名前だけの一覧は使えません。
投稿できるかどうかが分からないからです。**1件でも規約原文が引用された場所があるほうが、
条件不明の場所が10件並ぶより価値があります。**

#### 3. この層にとって、この値段は合っているか

`state/gumroad.json` の値段と比べてください。

**前回は開発者向け市場（itch・CodeCanyon・Unity Asset Store など）の相場を調べました。
今回はそこではありません。** 小さな事業者が、自分のサイトに置く仕掛けに
**普段いくら払っているか**です。制作外注・月額サービス・買い切り素材、
どの形でも構いませんが、**どの形かを明記してください。**

- 実例と**出典URL**
- `state/gumroad.json` の値段は、この層から見て高いか安いか妥当か
- **形が合っていないなら、そう書いてください。**
  値段ではなく売り方の問題なら、それが答えです

### 出力の形

- **上の3つを、それぞれ別の節にしてください。** 混ざると使えません
- 実例には**出典URL**を必ず付けてください。URLの無い主張は書かないでください
- 実例は各節**4件まで**。届かなかった実例は**2件まで**

最後に `## 判定` を置き、次の3つに答えてください。

- **この層に、実際に金を払った実例があるか**（あり／なし／未確認）
- **実績ゼロのアカウントが、その日のうちに投稿できる場所が最低1つあるか**
  （あり／なし。**あるなら場所の名前と、条件が無いことの出典**）
- **落とすに足る材料が出たか**（出たなら、はっきり「落ちる」と書いてください）

**通すためではなく、落とすために調べてください。**
この持ち主にとって、**早く落ちるほうが、遅く落ちるより価値があります。**

**確かめられなかったことは「確かめられなかった」と書いてください。**
それは失敗ではありません。**埋めるために推測を書くほうが害です。**
