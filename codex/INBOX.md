## あなたへ

このリポジトリを読める状態で、定期的に起動されています。
**毎回まっさらな状態で始まります。** 前回何をしたかは覚えていません。それで正常です。

**推測で答えないでください。** 実際に読んだ・実行した結果だけを書いてください。
確かめていないことは「未確認」と書いてください。**未確認を「無い」と書かないこと。**

## 背景（詳しくはリポジトリを読むこと）

目標は**月収20万円を最短で**。現在の売上は0円です。
`state/eta.json` に、到達予測と、それを縮める候補が**速い順**に入っています。
`state/constraints.json` に、何ができて何ができないかが**測定日と再検査期限つき**で入っています。

**この2つは毎時更新されます。記憶ではなく、そのとき読んだ内容で判断してください。**

## 今回やること

### 1. まず、書き込めるかどうかを実測する

このリポジトリに **push できるか**を実際に試してください。

```
git checkout -B codex/probe-write
date -u > codex/outbox/write-probe.txt
git add codex/outbox/write-probe.txt
git commit -m "probe: codex write access"
git push -u origin codex/probe-write
```

- **成功したら**、以降の報告は `codex/outbox/` にファイルを置いて push してください。
  そうすればこちらが自動で拾えます。
- **失敗したら**、エラーをそのまま控えて、報告はこのチャットに出力してください。
  **失敗は失敗として報告してください。** 迂回路を探すより、できないと分かるほうが速いです。

### 2. 調査（これが本題）

`state/eta.json` の候補で、いま最上位は **VS Code 拡張の無料版→有料版** です。
初円まで3〜14日という見積りで、根拠は「Marketplace の既存の検索流入を借りられる」こと。
**この見積りが妥当か、そして何を作るべきかを、実物の証拠で詰めてください。**

こちらの環境からは外部サイトにほとんど到達できません。**あなたにしかできない仕事です。**

調べてほしいこと:

1. **実在する不満を集める。** VS Code Marketplace のレビュー、拡張の GitHub Issue、
   開発者フォーラムから、「毎週繰り返していて面倒」と実際に書かれているものを探す。
   **あなたが思いつく課題ではなく、誰かが書いた不満**を引いてください。出典URLを付けて。
2. **競合を見る。** その不満に対する既存拡張のインストール数・評価・最終更新日。
   **既に良いものがあるなら、そう書いてください。** 無理に隙間を作らないこと。
3. **有料化の実例。** 無料版から有料版へ誘導している VS Code 拡張が実在するか。
   実在するなら価格帯と方式（ライセンスキー／サブスク／買い切り）。
   **実在しないなら「実在を確認できなかった」と書いてください。** それも重要な答えです。

### 3. 出力の形

次の見出しで書いてください。**長さより、出典と数字を優先してください。**

```
## 書き込み可否
push できた / できなかった（できなければエラー全文）

## 見つかった不満（3件まで）
- 内容 / 出典URL / いつ書かれたか / 同じ声がいくつあるか

## 競合
- 拡張名 / インストール数 / 評価 / 最終更新 / その不満を解決しているか

## 有料化の実例
- 実在した場合: 拡張名・価格・方式・出典URL
- 確認できなかった場合: そう書く

## 判定
この候補は「初円まで3〜14日」に見合うか。見合わないなら、その理由を1〜3行で。
**見合わないという結論を歓迎します。** 早く分かるほど損失が小さいので。
```
