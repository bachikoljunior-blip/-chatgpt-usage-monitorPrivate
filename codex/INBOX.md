## 起動したらまず（**定期実行なので、毎回ここから**）

あなたは定期的に、毎回まっさらな状態で起動されます。前回の記憶はありません。

**期限とマーカーの確認は、あなたの仕事ではありません。**
`.github/workflows/codex-inbox.yml` が `scripts/inbox-task.mjs` を先に走らせ、
`valid_until` が過ぎているか `done_marker` が既にあるなら、
**あなたはそもそも起動されません。** あなたが動いているなら、この task は
「期限内・未実行」だと確認済みです。**もう一度確かめ直さないでください。**

**push しないでください。届きません。** あなたが動いているサンドボックスの作業場所は
チェックアウトの外にあり、リポジトリにも資格情報にも届かないように作ってあります。
2026-08-09 まで、この指示は「push できるか試して、できなければ調査せず終えろ」と
書いてありました。**この経路では push は絶対にできないので、その指示のままだと
この口は永久に空振りするだけでした。**

**あなたの回答は、ワークフローが自動でコミットします。**
完了マーカー（`done_marker`）も、あなたの回答からワークフローが作ります。
だから**あなたがやることは、下の「今回やること」を実行して、答えを書くことだけ**です。

**ファイルを探さないでください。** 2026-08-09 の最初の実行で分かったことです。
あなたは空の作業ディレクトリで起動され、`codex/INBOX.md` も git も見つけられず、
「作業ディレクトリが空です」の一文だけを返して終わりました。**それが正常な挙動です。**
だから今は、**必要なものは全部あなたへの入力に貼り付けてあります**
（この指示の全文と、下の「背景」が挙げている `state/` のファイルの中身）。
**どのファイルが付いているかは、この本文の `=====` の見出しを見れば分かります。**
毎回その場で読み出して貼っているので、**古いことはありません。**

**`## 判定` の見出しを必ず書いてください。** ワークフローはこの文字列を探して、
「本当に仕事をしたか」を判定します。無ければマーカーを置かず、明日もう一度来ます。
**中身が無いのに見出しだけ書くのはやめてください。** それは仕組みを騙すだけで、
騙した先に得をする人がいません。

**答えが空なら、マーカーも残りません。** 明日もう一度この task が来ます。
それは正しい動作です。**空振りを隠すために、中身のない答えを書かないでください。**

**「確かめられなかった」は正しい答えです。** 空振りの回に仕事を作り出さないでください。

## 今回やること

### 今回は「候補の形」ではなく、**この持ち主が実際に持っている物**の話です

これまでの調査（`state/eta.json` の `refuted` を読んでください）は、
**まだ作っていない案**を落とすためのものでした。全部落ちました。
落ち方には共通の形があります。**買い手が自分から届いた実例が、暦日つきで一件も無い。**

今回はそこから向きを変えます。**すでに存在して、すでに値段が付いているもの**についてです。

**貼り付けた `state/gumroad.json` を見てください。** 公開済みの商品が入っています。
**名前と値段はそこにあります。ここには書きません。**
`state/portfolio.json` には、同じ持ち主が公開している無料のものが並んでいます。
**その中に、有料商品の中身をそのまま遊べる形にしたものがあります。**
どれのことかは、両方を読めば分かります。**こちらの説明ではなく、そちらを読んでください。**

つまり「すぐ試せる無料のもの」と「その先に置いてある有料のもの」が、
**もう両方そろっています。** 足りていないのは、そこへ人が来る経路だけです。
`state/eta.json` の `channels` にある `gumroad` の `idle_eta_reason` が、そう書いてあります。

### 訊きたいこと（**4つ。それぞれ別の節で答えてください**）

#### 1. この有料商品を、実際に金を払って買うのは誰か

`state/gumroad.json` の商品名と値段を読んでから答えてください。

**「買いそうな人」ではありません。** 同じ種類のもの
（ゲームやアプリの**ソースコードや制作キットを、商用利用の権利つきで売る**もの）に
**実際に金を払った人**の実例を探してください。

- 買った人は何者だったか（個人開発者・広告代理店・受託・教育・その他）
- 何のために買ったか
- **出典URLを必ず付けてください**

#### 2. その買い手は、どこに集まっているか

**具体的な場所の名前**を挙げてください。掲示板・subreddit・Discord・
マーケットプレイス・メーリングリスト、何でも構いません。

**そして、場所ごとに次を必ず調べてください。ここが今回の核心です。**

- **その場所の規約は、自分の商品の宣伝投稿を許しているか。**
  許していないなら、**該当する規約の文言をそのまま引用**してください
- **できたばかりの、実績ゼロのアカウントでも投稿できるか。**
  カルマ・アカウント年齢・過去の参加回数・承認制など、**投稿の前提条件**があるなら、
  その**数値と出典**を書いてください
- 条件が無いなら「無し」と書いてください。**「たぶん大丈夫」は書かないでください**

**この項目が空欄のままなら、今回の調査は失敗です。** ほかが埋まっていても、
どこにも投稿できないなら残りは使えません。

#### 3. 「実績ゼロだが、同じ日に複数の場所へ出した」先例

貼り付けた `state/constraints.json` の `no_standing_where_buyers_gather` を読んでください。
**そこに書いてある仮説を落とすために調べます。**

- **フォロワーも実績も無い状態から、同じ日に複数の場所へ出して初売上に届いた実例**
  （**公開日と初売上日の両方が暦日で確認できるもの**を優先。確認できなければ「日付未確認」）
- 逆に、**同じことをやって届かなかった実例**（削除された・無視された・
  規約違反で消された）。**どこで止まったか**を書いてください

**通すためではなく、落とすために調べてください。**

#### 4. 値段は市場と合っているか

同じ種類の商品（ゲームやアプリのソースコード・制作キットの商用ライセンス）が
**実際いくらで売られているか**、実例を挙げてください。
`state/gumroad.json` の値段と比べて、高いか安いか妥当かを書いてください。

### 出力の形

- **上の4つを、それぞれ別の節にしてください。** 混ざると使えません
- 実例には**出典URL**を必ず付けてください。URLの無い主張は書かないでください
- 実例は各節**4件まで**。届かなかった実例は**2件まで**

最後に `## 判定` を置き、次の4つに答えてください。

- **この有料商品に、金を払った実例のある買い手層が実在するか**（あり／なし／未確認）
- **実績ゼロのアカウントが、その日のうちに投稿できる場所が最低1つあるか**
  （あり／なし。**あるなら場所の名前と、条件が無いことの出典**）
- **実績ゼロから同じ日に複数の場所へ出して初売上に届いた実例があるか**
  （あり／なし／日付未確認）
- **落とすに足る材料が出たか**（出たなら、はっきり「落ちる」と書いてください）

**確かめられなかったことは「確かめられなかった」と書いてください。**
それは失敗ではありません。**埋めるために推測を書くほうが害です。**

**とくに、規約や投稿条件を確認せずに場所の名前だけ並べないでください。**
名前だけの一覧は、こちらでは使えません。投稿できるかどうかが分からないからです。
