## 起動したらまず（**定期実行なので、毎回ここから**）

あなたは定期的に、毎回まっさらな状態で起動されます。前回の記憶はありません。

**期限とマーカーの確認は、あなたの仕事ではありません。**
`.github/workflows/codex-inbox.yml` が `scripts/inbox-task.mjs` を先に走らせ、
`valid_until` が過ぎているか `done_marker` が既にあるなら、
**あなたはそもそも起動されません。** あなたが動いているなら、この task は
「期限内・未実行」だと確認済みです。**もう一度確かめ直さないでください。**

**push しないでください。届きません。** あなたが動いているサンドボックスの作業場所は
チェックアウトの外にあり、リポジトリにも資格情報にも届かないように作ってあります。
2026-08-09 まで、この指示は「push できるか試して、できなければ調査せず終えろ」と
書いてありました。**この経路では push は絶対にできないので、その指示のままだと
この口は永久に空振りするだけでした。**

**あなたの回答は、ワークフローが自動でコミットします。**
完了マーカー（`done_marker`）も、あなたの回答からワークフローが作ります。
だから**あなたがやることは、下の「今回やること」を実行して、答えを書くことだけ**です。

**ファイルを探さないでください。** 2026-08-09 の最初の実行で分かったことです。
あなたは空の作業ディレクトリで起動され、`codex/INBOX.md` も git も見つけられず、
「作業ディレクトリが空です」の一文だけを返して終わりました。**それが正常な挙動です。**
だから今は、**必要なものは全部あなたへの入力に貼り付けてあります**
（この指示の全文と、`state/eta.json`・`state/constraints.json` の中身）。
毎回その場で読み出して貼っているので、**古いことはありません。**

**`## 判定` の見出しを必ず書いてください。** ワークフローはこの文字列を探して、
「本当に仕事をしたか」を判定します。無ければマーカーを置かず、明日もう一度来ます。
**中身が無いのに見出しだけ書くのはやめてください。** それは仕組みを騙すだけで、
騙した先に得をする人がいません。

**答えが空なら、マーカーも残りません。** 明日もう一度この task が来ます。
それは正しい動作です。**空振りを隠すために、中身のない答えを書かないでください。**

**「確かめられなかった」は正しい答えです。** 空振りの回に仕事を作り出さないでください。

`refuted` が付いていないもののうち、いちばん上にあるものが今回の対象です。

こちらの環境からは外部サイトにほとんど到達できません。**あなたにしかできない仕事です。**

調べてほしいこと:

1. **実在する不満を集める。** その候補の市場（プラグインディレクトリのレビュー、
   GitHub Issue、フォーラム）から、「毎週繰り返していて面倒」と**実際に書かれている**
   ものを探す。**あなたが思いつく課題ではなく、誰かが書いた不満**を。出典URLを付けて。
2. **競合を見る。** その不満に対する既存製品のインストール数・評価・最終更新日。
   **既に良いものがあるなら、そう書いてください。** 無理に隙間を作らないこと。
   **特に、プラットフォーム本体が標準機能で解決していないか**を先に確かめること。
   前回それを見落とすところでした（VS Code 本体が既に解決していた）。
3. **有料化の実例。** 無料版から有料版へ誘導している実例がその市場に実在するか。
   実在するなら価格帯と方式（ライセンスキー／サブスク／買い切り）。

4. **初円までの日数。** 「公開から最初の1件が売れるまで」が分かる実例を探す。
   **これが見積りの検証点です。** 見つからないなら「確認できなかった」と書くこと。
