## 起動したらまず（**定期実行なので、毎回ここから**）

あなたは定期的に、毎回まっさらな状態で起動されます。前回の記憶はありません。

**期限とマーカーの確認は、あなたの仕事ではありません。**
`.github/workflows/codex-inbox.yml` が `scripts/inbox-task.mjs` を先に走らせ、
`valid_until` が過ぎているか `done_marker` が既にあるなら、
**あなたはそもそも起動されません。** あなたが動いているなら、この task は
「期限内・未実行」だと確認済みです。**もう一度確かめ直さないでください。**

**push しないでください。届きません。** あなたが動いているサンドボックスの作業場所は
チェックアウトの外にあり、リポジトリにも資格情報にも届かないように作ってあります。

**あなたの回答は、ワークフローが自動でコミットします。**
完了マーカー（`done_marker`）も、あなたの回答からワークフローが作ります。
だから**あなたがやることは、下の「今回やること」を実行して、答えを書くことだけ**です。

**ファイルを探さないでください。** あなたは空の作業ディレクトリで起動されます。
**必要なものは全部あなたへの入力に貼り付けてあります。**
**どのファイルが付いているかは、この本文の `=====` の見出しを見れば分かります。**

**`## 判定` の見出しを必ず書いてください。** ワークフローはこの文字列を探して、
「本当に仕事をしたか」を判定します。無ければマーカーを置かず、明日もう一度来ます。
**中身が無いのに見出しだけ書くのはやめてください。**

**「できなかった」は正しい答えです。** 前回、あなたが5番を拒否したのは正しい判断でした。
根拠が添付に無い数字を作らなかったからです。**今回も同じ基準で拒否してください。**

目標は**月収20万円を最短で**。売上の現在値は貼り付けた `state/gumroad.json` にあります。

貼り付けてあるもの:

- `state/gumroad.json` — **値段が付いている唯一のもの**と、その売上実績
- `assets/listing/gumroad.ja.json` — **今まさに店頭に出ている日本語のコピー全文**（今回から添付）

**記憶ではなく、貼り付けられた内容で判断してください。**

## 今回やること（**2件だけです。1番が本体、2番は短い調べもの**）

### 1. 店頭のコピーを英語にする（**ゼロから書き直さないでください**）

添付の `assets/listing/gumroad.ja.json` にある `name` と `description_html` が、
**いま実際に店頭に出ている文章**です。**その英語版**を作ってください。

**これは翻訳ではなく翻案です。** 直訳ではなく、英語圏の買い手にそのまま通じる文章に
してください。ただし**中身の主張を足さないこと**。同梱していないものを同梱していると
書いた時点で返金になり、こちらの損です。

**必ず守ること:**

- 同じファイルの `addressee` が、**この文章が話しかける相手**です。
  店・サロン・配信者に向けて書かないでください。**自分の作品として1本出す人**が相手です。
- 同じファイルの `addressee_terms.forbidden` にある日本語表現に相当する英語
  （自社ブランド / 店舗サイト / キャンペーンページ など）を**使わないでください**
- **同梱の README・設定検査（validate_config.py）の出力・ライセンス文は日本語です。**
  英語話者がそのまま読めるのは**コードと設定ファイルだけ**です。
  **この事実を目立つ場所に、はっきり書いてください。** 隠すと返金になります
- ライセンスの範囲を**広げないこと**。`description_html` が書いている条件
  （公開先1つ・商用可・改変可・キット自体の再販は不可・受託納品は別途相談）が上限です。
  英語のほうが緩く読める書き方をしないでください

**出力の形:** `name` に当たる**英語のタイトル1行**と、`description_html` に当たる**本文**を、
別々に、**そのまま貼れる形で**出してください。本文は HTML（`<p>` `<ul>` `<h3>` 程度）で結構です。

### 2. Gumroad Discover の分類を1つ調べる（**外部を読んでください**）

こちらの環境からは Gumroad の公開ページにほとんど到達できません。あなたは読めます。

Gumroad の Discover（`https://gumroad.com/discover` とその配下）を実際に開いて、
**この商品——ゲーム開発者向けの、HTML/CSS/JS の放置クリッカー製作テンプレート——を
置くのに一番近いカテゴリはどれか**を答えてください。

**答えてほしいのは次の3つです:**

1. **カテゴリの名前と、その URL**（`https://gumroad.com/discover/...` の実際の形）。
   親子関係があるなら親も。**開いて確認した URL だけ**を書いてください
2. そのカテゴリに**実際に並んでいる商品**を3件、名前だけで結構なので挙げてください。
   これは「そのカテゴリが空の飾りではない」ことの確認です
3. **`taxonomy_id` の数値が外から分かるか。** 分かるならその値と、どこで見たか。
   **分からないなら「分からない」と書いてください。** それが正しい答えである可能性が高いです

**推測で数値を書かないでください。** こちらはこの数値を live の商品に書き込みます。
**間違った分類は `other` のままより悪いです。**「分からない」なら `other` のままにします。

### 出力の形

- 上の2つを、**番号と名前をそのまま見出しにして**、それぞれ別の節に
- できなかった節は、その見出しの下に「できない」と理由を1行
- **推測を書かないでください。** 出せなかったものを出せたことにしないでください

最後に `## 判定` を置き、次に答えてください。

- **1と2のうち、現物が出たのはどれか**
- **2番で、実際に開けた URL はいくつか。** 0 なら、この経路から Gumroad が
  読めないという測定結果です。そう書いてください
- **1番の英文に、日本語ドキュメントの但し書きを入れたか**（入れた／入れていない）
- **この2つ以外に、いまのこちらの詰まり（添付の `state/eta.json` の候補一覧を見てください）
  に対してあなたが確実に出せるものがあるか。** あるなら、
  **次回それを現物で出せる形の依頼文**を1つ書いてください。こちらがそのまま次の task にします

**通すためではなく、境界を見つけるために出してください。**
