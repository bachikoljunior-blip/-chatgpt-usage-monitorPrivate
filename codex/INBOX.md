## 起動したらまず（**定期実行なので、毎回ここから**）

あなたは定期的に、毎回まっさらな状態で起動されます。前回の記憶はありません。

**期限とマーカーの確認は、あなたの仕事ではありません。**
`.github/workflows/codex-inbox.yml` が `scripts/inbox-task.mjs` を先に走らせ、
`valid_until` が過ぎているか `done_marker` が既にあるなら、
**あなたはそもそも起動されません。** あなたが動いているなら、この task は
「期限内・未実行」だと確認済みです。**もう一度確かめ直さないでください。**

**push しないでください。届きません。** あなたが動いているサンドボックスの作業場所は
チェックアウトの外にあり、リポジトリにも資格情報にも届かないように作ってあります。

**あなたの回答は、ワークフローが自動でコミットします。**
完了マーカー（`done_marker`）も、あなたの回答からワークフローが作ります。
だから**あなたがやることは、下の「今回やること」を実行して、答えを書くことだけ**です。

**ファイルを探さないでください。** あなたは空の作業ディレクトリで起動されます。
**必要なものは全部あなたへの入力に貼り付けてあります。**
**どのファイルが付いているかは、この本文の `=====` の見出しを見れば分かります。**

**`## 判定` の見出しを必ず書いてください。** ワークフローはこの文字列を探して、
「本当に仕事をしたか」を判定します。無ければマーカーを置かず、明日もう一度来ます。
**中身が無いのに見出しだけ書くのはやめてください。**

**「できなかった」は正しい答えです。** 前回、あなたが `taxonomy_id` を
「分からない」と書いたのは正しい判断でした。**今回も同じ基準で拒否してください。**

## 今回やること（**投稿先を3つ、規約ごと調べる**）

売るものは、貼り付けた `state/gumroad.json` と `assets/listing/gumroad.ja.json` にあります。
**その商品の買い手が既に集まっている場所を3つ**選び、**1つずつ**次の4点を答えてください。

**選ぶ基準（ここを外すと全部無駄になります）:**

- **買い手がいる場所**であって、作り手だけが集まる場所ではないこと
- **今日、新規アカウントで投稿できる**こと。承認制・招待制・有料会員制はここでは除外
- **英語圏で構いません。**同梱ドキュメントは日本語ですが、
  `.n` の英語コピーがあり、コードと設定は英語話者がそのまま読めます

### 各1件について答えること

1. **名前と URL。** 実際に開いた URL だけを書いてください
2. **自己宣伝に関する規約の該当箇所を、原文のまま引用**してください。
   要約しないこと。**引用が無い venue は、無かったものとして落としてください。**
   規約が「自己宣伝は全面禁止」なら、それを引用してそう書いてください。それも答えです
3. **投稿の資格条件。** アカウント年齢、カルマ、投稿回数、曜日限定スレッドの有無など、
   **数値で書いてあるものを数値のまま。** 「特に無い」ならそう書いてください
4. **その venue に、規約に沿って出せる形が実在するか。**
   専用の曜日スレッド、`[Showoff]`、`Self-promotion Saturday` のような枠があるなら、
   **その枠の URL と、直近に実際に投稿がある日付**を1つ

### やってはいけないこと

- **投稿しないでください。** これは調査だけです。アカウントも作らないでください
- **規約を要約しないでください。** こちらが判断します。引用が要ります
- **推測で venue を埋めないでください。** 3つ出せなければ2つでも1つでも構いません。
  **開いていない URL を書かないこと。** 数を揃えるより、開いた事実のほうが要ります

### 出力の形

- venue ごとに1節。見出しはその venue の名前
- 各節に上の1〜4を、番号のまま
- 出せなかった項目は、その番号の下に「できない」と理由を1行

最後に `## 判定` を置き、次に答えてください。

- **実際に開いた URL はいくつか**（数字で）
- **規約の原文引用が取れた venue はいくつか**（数字で。取れていないものは venue として数えないこと）
- **3件のうち、新規アカウントで今日投稿できるものはいくつか**
- **この3件以外に、いまのこちらの詰まり（添付の `state/eta.json` の候補一覧を見てください）
  に対してあなたが確実に出せるものがあるか。** あるなら、
  **次回それを現物で出せる形の依頼文**を1つ書いてください。こちらがそのまま次の task にします
