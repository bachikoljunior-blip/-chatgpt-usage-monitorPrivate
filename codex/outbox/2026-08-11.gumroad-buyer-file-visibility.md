## 判定

**総合判定：分からない。**

より細かく分けると、公開情報からかなり強く言えるのは次の範囲です。

- 通常の購入者向けコンテンツ画面に表示されるファイル：**rich content に埋め込まれた1つだけ**と読むのが妥当
- 商品に添付されているが rich content に埋め込まれていないもう1つ：**通常画面に自動表示されるとは確認できない**
- 「Download all」または一括 ZIP：埋め込まれていない添付まで含めて**2つ全部になるかは、公開資料では確定できない**

したがって、「購入者が最終的に取得可能なのは1つか2つか」という質問全体には、**分からない**が正しい回答です。「画面に見えるもの」に限れば、公式説明は1つを指しています。

## 公式の記述

### 購入者画面は Content editor の内容

Gumroad公式ヘルプは、Contentタブでファイル等を追加し、購入者には “just as you see it in the editor” と表示されると説明しています。[Adding a product](https://gumroad.com/help/article/149-adding-a-product)

これは、rich content に1ファイルしか配置されていないなら、通常の購入者画面でもその1ファイルだけが表示される、という強い根拠です。

同じヘルプは、フォルダを「download page」で開閉するとも説明しています。つまり現在のContent editorは単なる説明文ではなく、購入者のダウンロード画面そのものを構成します。

### rich content 導入時の説明

公式ブログは、新Content editorについて、ファイルをエディタ内に埋め込み、それが全購入者向けに働くと説明しています。[Create your content within Gumroad](https://gumroad.com/blog/p/create-your-content-within-gumroad)

ここでも、購入者が見る対象は「添付ファイル集合」ではなく、エディタで構成したコンテンツだと読めます。

### Download all

公式ヘルプは、商品の合計コンテンツサイズが500MB未満なら「Download all」を表示すると説明しています。[File size limits](https://gumroad.com/help/article/289-file-size-limits-on-gumroad.html)

ただし、ここでいう “content” が、

- rich content に埋め込まれたファイルだけ
- 商品レコードに紐づく全添付ファイル

のどちらなのかは書かれていません。したがって、今回の「添付2つ、埋め込み1つ」について一括ダウンロードの収録範囲は確定できません。

ZIPファイルを商品へ直接アップロードすれば全内容を一度に取得させられる、という記述はありますが、これはGumroadが動的に作る一括ZIPの収録規則を説明するものではありません。

### API資料

公開されたGumroadのAPI関連資料では、`files` と `rich_content` は別のフィールドとして扱われています。rich content側には「file embeds / file groups」があると明記されています。[API planning issue](https://github.com/antiwork/gumroad/issues/4019)

また公式CLI資料は、`--file` が既存の “rich content file embeds” を置換し、埋め込みがなければ新しく作る、と説明しています。[Gumroad CLI skill](https://github.com/antiwork/gumroad-cli/blob/main/skills/gumroad/SKILL.md)

これは次の区別を裏づけます。

- ファイルが商品に所属していること
- そのファイルがrich contentに埋め込まれていること

ただし、API/CLI資料には「購入者のDownload allが、埋め込まれていない`files`も含む」とも「除外する」とも書かれていません。`file_info`についても、購入者側の表示との対応を説明する公開記述は見つかりませんでした。

## 実体験の報告

今回の条件を満たす実体験、すなわち、

- 同一商品に2ファイル添付
- rich contentには1ファイルだけ埋め込み
- 購入者側で何ファイル見えたかを確認

という報告は見つかりませんでした。

特に探した3種類についての結果は以下です。

- 「添付したのに買った人に見えない」：今回のrich content構成に結びつく報告は**なし**
- 「コンテンツページを作ると、埋め込んでいないファイルが消える」：明示的な報告は**なし**
- 「コンテンツページがあっても添付ファイルは全部出る」：明示的な報告は**なし**

近い購入者報告として、iPad上でダウンロードボタン自体が見えないという投稿はありましたが、アプリ内ブラウザ／端末側の問題とされており、今回の埋め込み範囲とは無関係です。[Reddit: Gumroad brushes on iPad](https://www.reddit.com/r/procreatebrushes/comments/1d2ofvm)

したがって、実体験から1つ／2つを決める根拠はありません。

## 推測

公開情報を組み合わせた推測は次のとおりです。

1. 通常画面では1つだけ  
   公式が「購入者はエディタで見える通りに見る」と明記しているためです。

2. 個別の「Download」も埋め込まれた1つだけ  
   ファイルごとのボタンはrich contentのファイルブロックに付くと考えるのが自然です。

3. 「Download all」は不明  
   商品に所属する全ファイルをバックエンドで集める実装なら2つ、rich content内のファイルブロックだけを集めるなら1つです。公開ヘルプもAPI資料も、この境界を説明していません。

以上は、1と2が公式記述に基づく強い推論、3は未解決です。

## 購入せずに確定させる方法

**実際に課金して購入する必要はありません。公式のtest purchase機能があります。**

Gumroadは、売り手がログインした状態で自分の商品をテスト購入し、購入者が見る画面とファイル配信を確認できると説明しています。料金は請求されません。[Testing a purchase](https://gumroad.com/help/article/62-testing-a-purchase)

手順：

1. Gumroadの販売者アカウントにログインする
2. 対象商品のContent editorを開き、2ファイルが添付され、rich contentには1つだけ表示されている状態を保存する
3. 商品の購入ページを開く
4. 購入ボタンからチェックアウトへ進む
5. 支払方法が「Test card」になっていることを確認する
6. テスト購入を完了する
7. 購入後の「View content」を開く
8. 次を別々に記録する
   - 画面に表示されるファイル名
   - 各ファイルのDownloadボタン
   - Download allの有無
   - Download allで得たZIPの中身
9. 必要ならrich contentから全ファイルを外した対照条件でも同じテストをする

これは「実際の購入」ではなく、Gumroadが公式に用意している無課金の配信確認です。今回の問いを確定させる最短かつ公式な方法です。Content editorの表示確認だけでも通常画面は推定できますが、Download allの内容まで確定するにはtest purchaseが必要です。
