## 判定

**ブラウザ操作以外の口は、現在はあります。**

ただし、添付ファイル専用の `DELETE` エンドポイントではありません。Gumroad が公開している公式 CLI と公開ソースが示す方法は、商品の **rich content 全体を読み出し、削除したいファイル埋め込みを除いた文書を `PUT /v2/products/:id` で丸ごと置換する**方法です。

今回実測された、平坦な `files[]` に残すファイルだけを入れる方法とは別経路です。rich content を持つ商品では、ファイルは単なる product-level `files[]` ではなく、コンテンツページ内の file embed として管理されます。

具体形は次のとおりです。

1. 現在の rich content を取得する。

   ```text
   gumroad products content get <product_id> --json --no-input > content.json
   ```

2. `content.json` 内から、外したい古いファイルの埋め込みノードだけを削除する。残すページの `id` と、残すテキスト・フォルダ・ファイル埋め込みは維持する。

3. まず dry-run する。

   ```text
   gumroad products content set <product_id> content.json \
     --dry-run --json --no-input
   ```

4. 実行時の形は以下。ただし、この調査では実行していない。

   ```text
   gumroad products content set <product_id> content.json \
     --yes --json --no-input
   ```

CLI の下で使われる HTTP の具体形は次です。

```http
PUT /v2/products/:id
Authorization: Bearer <edit_products 権限を持つ seller OAuth token>
Content-Type: application/json

{
  "rich_content": [
    {
      "id": "<既存ページID>",
      "...": "既存ページのその他の値",
      "content": [
        "<残すノードだけ。古いファイルの埋め込みノードを除く>"
      ]
    }
  ]
}
```

必要な値は、商品 ID、`edit_products` 権限のトークン、現在の rich content 全体、残すページ ID・ノード・ファイル埋め込みです。

[Gumroad 公式 CLI の指示](https://github.com/antiwork/gumroad-cli/blob/main/skills/gumroad/SKILL.md)は、whole-document `set` が文書全体を置換し、既存ページを省略すると削除になること、削除を伴う更新には確認が必要なことを明記しています。また `products update --file` は、rich content 内の既存 file embed を位置対応で置換する機能であり、構造的な削除には `products content get/set` を使うよう案内しています。

したがって今回の最も安全な候補は、`files[]` を再送することではなく、**現在の `rich_content` を取得し、その中の古い file embed 一個だけを除いて全体を戻すこと**です。

## DELETE エンドポイント

商品配下で、通常の納品ファイルを一個だけ消す次のような公開エンドポイントは見つかりませんでした。

```text
DELETE /v2/products/:product_id/files/:file_id
DELETE /v2/products/:product_id/attachments/:attachment_id
DELETE /v2/files/:file_id
```

公開情報で確認できた `DELETE` は別物です。

- `DELETE /v2/products/:id` — 商品全体の削除
- `DELETE /v2/products/:product_id/variant_categories/:id` — variant category 全体の削除
- cover、thumbnail、公開 media には個別削除機能があるが、購入者向け納品ファイルの削除ではない

従って「product 配下に file ID を渡す DELETE があるか」への答えは、**探した範囲では見つからない**です。「存在しないと公式が明言した」わけではありません。

## rich content で挙動が変わる根拠

2026年3月の公式リポジトリの設計記録では、product API の当初案は uploads と rich content を対象外にしていました。その後、Gumroad 側メンバーが rich content を v1 に含める方針へ変更し、次を明記しています。

- file embeds / file groups を含む rich content
- seller-scoped files presign
- variant rich content
- product API response に rich content / files を追加
- product update API を追加

出典は [API for creating and editing products #4019](https://github.com/antiwork/gumroad/issues/4019) です。

これは重要です。古い API 解説やクライアントは rich content 更新が導入される前の仕様を説明している可能性があります。現在の公式 CLI は、shared product content と per-variant content を別々に取得・置換する機能を持っています。

公式ヘルプも現在の商品編集画面について、ファイルは Content ページ内に置かれ、ページ・フォルダ・variant ごとの content として編成されると説明しています。[Adding a product](https://gumroad.com/help/article/149-adding-a-product)、[Setting up versions](https://gumroad.com/help/article/126-setting-up-versions-on-a-digital-product)。

## 「API では消せない」という公式明言

**見つかりませんでした。**

これは「消せない」と同じではありません。今回見つかった新しい公式 CLI は、むしろ rich content の全体置換による削除を想定しています。

区別すると次のとおりです。

- 個別ファイル用 `DELETE`：探したが見つからなかった
- `files[]` の縮小による削除：提示された実測では効かなかった
- rich content から file embed を除く全体置換：公式 CLI が現在案内している
- 「API ではファイル削除不能」という公式文言：見つからなかった

## Zapier / Make / 公式インテグレーション

Zapier の公開 Gumroad コネクタに掲載されているのは Cancellation、Refund、New Product、Sale のトリガーで、「商品ファイルを削除」はありません。[Zapier Gumroad integrations](https://zapier.com/apps/gumroad/integrations)。

Make の Gumroad モジュール一覧は次です。

- Create a Product Category
- Get a Product
- Get a Sale
- Get a Subscriber
- List Products / Sales / Subscribers
- Make an API Call
- Watch New Cancellations / Sales

Gumroad 添付ファイル削除専用モジュールはありません。[Make Gumroad app documentation](https://apps.make.com/gumroad)。

Make の検索結果に出る “Delete a File/Folder” は Google Drive 側の操作であり、Gumroad の商品ファイル削除ではありません。

Make の “Make an API Call” なら理論上は rich-content `PUT` を送れますが、これは専用の「ファイル削除」操作ではありません。

## 変更履歴

「API からファイルを削除できるようになった／できなくなった」という名称の公式 changelog 項目は見つかりませんでした。

一方、公式 GitHub の [issue #4019](https://github.com/antiwork/gumroad/issues/4019) は実質的な変更記録です。

- 2026-03-18：商品 create/edit API を提案
- 2026-03-23：当初は uploads と rich content を v1 対象外
- 同日：rich content が販売に不可欠との判断で方針変更
- file embeds / file groups、presign、variant rich content を計画へ追加
- 現在の公式 CLI では `products content get/set` が公開されている

したがって、古い時点には存在しなかった rich-content 更新面が、2026年に追加されたと読むのが妥当です。ただし「ファイル削除機能」という名前で追加されたわけではなく、**rich content の置換機能の結果として削除できる**形です。

## 注意点

この操作は全体置換です。古いファイルだけでなく、誤って省略したページやノードも削除され得ます。

特に次を守る必要があります。

- 最初に `content get` で現物を取得する
- rich content の中で、削除対象の file embed を識別する
- それ以外のページ ID とノードを保持する
- dry-run の差分を確認する
- per-variant content がある場合、shared content と取り違えない
- 実行後は再取得し、古いファイルだけが消えたことを確認する

今回の商品については、「新しいアーカイブは rich-content ページに埋め込まれている」と提示情報にあります。古いアーカイブも同じ rich content に file embed として現れるなら、この方法が直接該当します。古いファイルが rich content のどこにも現れず、product-level files にしか現れない場合は、この方法で消えるとはまだ断定できません。その場合の最終判定は **分からない** に戻ります。
